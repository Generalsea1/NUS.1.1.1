# NUS — مصروفات مدير المنزل

## Product intent

«مصروفات مدير المنزل» هو مدير تدبير اقتصادي للأسرة، وليس دفتر تسجيل مصروفات فقط.

المستخدم يدخل دخله الشهري (أو مصادر دخله لاحقًا) ويحدد الأسرة والالتزامات والأولويات والاحتياجات. النظام يحول هذه البيانات إلى خطة قابلة للتنفيذ تساعد على جعل الدخل يكفي الشهر، ثم يراجع الواقع مقابل الخطة.

## Core promise

> من أقل مبلغ ممكن إلى أعلى دخل ممكن، ساعدني أن أدير منزلي وأسرتي بعقلية مدير اقتصادي يعرف ما يجب دفعه أولًا، وما يمكن تأجيله، وما يجب أن يكون له سقف، وما يجب الاحتفاظ به للطوارئ.

## Budget domains

- الدخل والمصادر الشهرية.
- السكن والإيجار.
- المرافق والفواتير.
- الأغذية والاحتياجات المنزلية.
- المواصلات والسيارة.
- الديون والأقساط.
- الصحة والدواء.
- الملابس.
- الصيانة والإصلاحات.
- الفسحة والاحتياجات العائلية.
- المصروفات الأخرى.
- الادخار والاحتياطي والطوارئ.

## Required outputs

The manager should be able to produce:

1. A monthly allocation plan.
2. Weekly spending limits/envelopes.
3. Priority ordering for mandatory vs. flexible spending.
4. Over-budget warnings and suggested reductions.
5. Reserve/emergency guidance.
6. Actual-vs-plan comparisons using the existing expense ledger.
7. Later: adaptive plans generated by an authenticated AI assistant using the user's historical data, priorities and household profile.

## Architecture contract

The existing Expense lifecycle remains the transaction ledger and must not be deleted or repurposed into budget logic.

The new household manager consumes the existing expense service and adds a planning domain above it.

The future AI layer must be provider-agnostic and server-side. Account registration/authentication can be introduced with Supabase without putting provider secrets in the client. The local planner remains useful when AI is unavailable.

## Non-goals for this phase

- No deletion of existing expense CRUD.
- No changes to reminder/scheduling behavior.
- No Supabase schema migration yet.
- No hard-coded AI vendor dependency.
- No assumption that one percentage rule fits every family.

The percentage/rule-based planner in this phase is a deterministic baseline only. Future iterations should incorporate household-specific priorities, history, due dates, seasonality, inflation-sensitive categories and AI-generated recommendations with explicit explanations.
